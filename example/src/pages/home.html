Why Aurelia 2 SSR over React Server Components (RSC)?

Compare the engineering trade-offs between serializing complex Virtual-DOM fiber graphs versus executing directly against Web Standards with real DOM semantics.

React Server Components (RSC) Heavy Boundary Tax
  • ✕ Mandates artificial 'use client' and 'use server' execution boundaries.
  • ✕ Heavy fiber reconciler bundled to browser (~45 KB+ baseline runtime).
  • ✕ Serializes complex flight JSON wire streams; difficult to debug or inspect.
  • ✕ Vendor lock-in often tightly coupled to proprietary hosting platforms.
Aurelia 2 + Hono SSR Direct Web Standards
  • ✓ Standard TypeScript classes and POJO ViewModels with zero boundary boilerplate.
  • ✓ Operates directly on standard native DOM platform with light-DOM slot projections (<au-slot>).
  • ✓ First-class Enterprise Dependency Injection container (Spring & C# grade IoC).
  • ✓ Thin Hono adapter: runs seamlessly on Bun, Cloudflare Workers, Node, or Deno.
